[s2] V  Binary and hexadecimal
  img: fig:binary
  • Each bit position is a power of 2
  • 10011100₂ = 128 + 16 + 8 + 4 = 156
  • Hex: each digit = 4 bits (0–9, A–F)
  • 1001 1100 → 9C → written 0x9C
  (pen marks: 9 )
  beat0:
     0: In binary, each position is a power of two instead of a power of ten: one, two, four, eight, sixteen, and so on, up to one hundred twenty eight for eight bits.
  beat1:
     0: To convert one zero zero one one one zero zero to decimal, add the place values where there's a one: one twenty eight plus sixteen plus eight plus four is one hundred fifty six.
     1: To go the other way, keep subtracting the largest power of two that fits.
  beat2:
     0: Long binary strings are hard for humans to read, so engineers use hexadecimal, base sixteen.
     1: Each hex digit stands for exactly four bits, using zero through nine and then A through F for ten through fifteen.
  beat3:
     0: Split the byte into groups of four: one zero zero one is nine, and one one zero zero is twelve, which is C.
     1: So the byte is nine C, written zero x nine C.
     2: You'll see hex everywhere: memory addresses, color codes like hash F F zero zero zero zero for red, and register values in a debugger.

[s4] V  Codes: BCD, ASCII and Gray code
  img: fig:gray / a:rotary_encoder
  • BCD: each decimal digit in 4 bits (calculators, clocks)
  • ASCII: 7-bit codes for text
  • Gray code: neighbors differ in exactly one bit
  • Used in rotary encoders to avoid glitches
  (pen marks: 7 )
  beat0:
     0: Bits can encode more than plain numbers.
     1: Binary coded decimal stores each decimal digit in its own four bits, which makes driving digit displays easy.
     2: ASCII, as you saw in programming, encodes text.
     3: And Gray code is a clever ordering where neighboring values differ in exactly one bit.
     4: Look at three to four.
     5: In normal binary, all three bits flip at once: zero one one becomes one zero zero.
     6: In real hardware, those bits never flip at exactly the same instant, so for a moment you might read a garbage value like one one one.
     7: In Gray code, three to four is zero one zero to one one zero.
     8: Only one bit changes, so there's no in between garbage.
  beat1:
     0: That's why rotary position sensors, like this encoder used to measure the angle of a motor shaft or a robot joint, mark their tracks in Gray code.
     1: It's also why the rows and columns of the Karnaugh maps you're about to learn are in Gray order.

[s5] V  From transistors to gates: the CMOS inverter
  img: fig:cmos
  • A transistor is a voltage-controlled switch
  • PMOS connects output to 1; NMOS connects it to 0
  • Exactly one is on → output = NOT input
  • Billions of these = a modern chip
  (pen marks: 6 )
  beat0:
     0: What's a logic gate made of?
     1: Transistors, used as switches.
     2: In today's C M O S technology, there are two kinds.
     3: A P M O S transistor turns on when its input is zero.
     4: An N M O S transistor turns on when its input is one.
  beat1:
     0: Put a P M O S between the power supply and the output, and an N M O S between the output and ground.
     1: That's an inverter.
  beat2:
     0: When the input is zero, the top switch closes and the bottom opens, so the output connects to one.
     1: When the input is one, it flips, and the output connects to zero.
     2: Exactly one switch is on at a time, which means almost no current flows when nothing is switching.
     3: That's why C M O S chips use so little power.
  beat3:
     0: Combine a few more transistors in series and parallel, and you get NAND and NOR gates.
     1: A modern processor is billions of these tiny switches.
     2: You'll study exactly how they work, and how fast they switch, in the electronics courses.

  (pen marks: 7 )

     1: AND outputs one only when both inputs are one.
     2: OR outputs one when either is.

[s7] V  Boolean algebra: simplifying logic
  img: fig:bool
  • A + A′ = 1 · A·A′ = 0 · A + 1 = 1 · A·1 = A
  • Distributive: AB + AC = A(B + C)
  • Example: AB + AB′ + A′B
  • = A(B + B′) + A′B = A + A′B = A + B
  (pen marks: 8 )
  beat0:
     0: Boolean algebra is the arithmetic of logic, where plus means OR, multiplication means AND, and a prime means NOT.
     1: Some rules look like normal algebra, and some don't.
     2: A plus not A is always one: something is either true or false.
     3: A times not A is always zero.
     4: A plus one is one.
  beat1:
     0: The distributive law lets you factor: A B plus A C equals A times B plus C.
  beat2:
     0: Why bother?
     1: Because simpler expressions mean fewer gates, which means less area, less power, and more speed.
     2: Let's simplify A B plus A B prime plus A prime B.
  beat3:
     0: Factor A out of the first two terms: A times B plus B prime, and B plus B prime is one, so that's just A.
     1: Now we have A plus A prime B.
     2: A useful identity says that equals A plus B.
     3: So three AND gates and an OR gate collapse into a single OR gate.
     4: That's a real saving, and the tools that design chips do this kind of simplification millions of times.

[s8] V  From a truth table to a circuit
  img: fig:majority
  • Write the truth table
  • OR together the rows where F = 1 (minterms)
  • Simplify
  • Majority vote: F = AB + AC + BC
  (pen marks: 3 )
  beat0:
     0: Any logic function can be built straight from its truth table.
     1: Here's a majority function: the output is one when at least two of the three inputs are one.
  beat1:
     0: For each row where the output is one, write an AND term that matches exactly that row.
     1: These terms are called minterms.
     2: Then OR them all together.
     3: That's called sum of products form, and it always works.
  beat2:
     0: But it's rarely the simplest.
     1: These four minterms simplify down to three terms.
  beat3:
     0: F equals A B plus A C plus B C: any two agreeing inputs win.
     1: This isn't just a toy.
     2: Spacecraft and aircraft computers use triple modular redundancy: three copies of the same circuit, with a majority voter on the output, so a single fault, like a radiation strike, gets outvoted.

[s9] V  Karnaugh maps: simplification by eye
  img: fig:kmap0 / fig:kmap1 / fig:kmap2
  beat0:
     0: Algebra works, but it's easy to miss a simplification.
     1: A Karnaugh map, or K map, makes it visual.
     2: Arrange the truth table in a grid with the rows and columns in Gray code order, so that neighboring cells differ by exactly one variable.
     3: Here's a four variable function, with ones in eight cells.
  beat1:
     0: Now circle groups of adjacent ones, in sizes that are powers of two.
     1: Within a group, any variable that changes drops out.
     2: This orange group of four covers rows where B equals one and columns where D equals one, while A and C both change.
     3: So the whole group simplifies to just B D.
  beat2:
     0: Here's the trick that surprises everyone: the map wraps around, like a donut.
     1: The four corners are all neighbors.
     2: They share B equals zero and D equals zero, so they form the group B prime D prime.
     3: The final answer is B D plus B prime D prime.
     4: Eight minterms with four variables each became two terms with two variables each.
     5: And notice that's actually an X N O R of B and D, which you might never have spotted from the equation.

[s11] V  Combinational building blocks
  img: fig:blocks
  (pen marks: 5 )
  beat0:
     0: Real designs aren't built gate by gate.
     1: They're built from standard blocks.
     2: A multiplexer selects one of several inputs using select lines, like a digital switch.
     3: A decoder takes an n bit number and activates exactly one of two to the n outputs, which is how memory chooses a row and how a C P U chooses which register to use.
     4: An encoder does the reverse.

     6: Comparators check whether two numbers are equal or which is bigger.

[s12] V  Memory from feedback: the SR latch
  img: fig:srlatch
  • Feed outputs back into inputs → the circuit can remember
  • S (set) = 1 → Q = 1
  • R (reset) = 1 → Q = 0
  • S = R = 0 → hold the last value
  (pen marks: 4 )
  beat0:
     0: Here's the most important trick in sequential logic: feedback.
     1: Take two NOR gates and connect each one's output to the other's input.
     2: The orange wires loop back.
  beat1:
     0: Pulse S, the set input, to one, and Q becomes one.
     1: Now let S go back to zero.
     2: Q stays at one, because the loop holds it there.
  beat2:
     0: Pulse R, the reset input, and Q flips to zero, and again stays there.
  beat3:
     0: With both inputs at zero, the circuit simply holds whatever it last stored.
     1: That's one bit of memory, made from two gates.
     2: It's called an S R latch.
     3: The one forbidden case is setting S and R to one at the same time, which leaves the latch in an undefined state when they're released.

[s13] V  Flip-flops, registers and counters
  img: fig:counter
  • D flip-flop: copies D to Q on the clock edge
  • Register: n flip-flops sharing a clock
  • Counter: register + adder (or toggling flip-flops)
  • Each bit toggles at half the rate of the one before
  (pen marks: 5 )
  beat0:
     0: Latches respond whenever their inputs change, which makes timing tricky.
     1: A flip-flop only updates at the instant the clock rises, the edge.
     2: A D flip-flop simply copies its D input to Q on each rising edge, then holds it.
  beat1:
     0: Put n flip-flops side by side with a shared clock and you have a register, which stores an n bit number.
     1: Every C P U register is exactly this.
  beat2:
     0: Feed a register's output through an adder that adds one, back into its input, and you have a counter.
     1: On every clock edge, the count goes up by one.
  beat3:
     0: Look at the timing diagram.
     1: Q zero toggles every clock cycle.
     2: Q one toggles at half that rate, and Q two at half again.
     3: Read the three bits together and they count zero, one, two, up to seven, then wrap around to zero.
     4: That halving is also why a counter makes a perfect clock divider.

[s15] V  Memory chips: addresses and data
  img: fig:memory

  • Address lines pick one word (decoder)

  • 2048 × 8 memory: 11 address lines, 8 data lines
  (pen marks: 4 )
  beat0:
     0: Scale that up and you get memory chips.
     1: A memory is a huge grid of storage cells, organized into words.
  beat1:
     0: To read or write, you send an address.
     1: A decoder turns that address into a single selected row, here highlighted in yellow, and that row's bits appear on the data lines.
  beat2:
     0: With n address bits, you can select two to the n words.
  beat3:

[s17] V  Putting it together: the structure of a computer
  img: a:i4004_layout / fig:cpu
  • Datapath: registers + ALU
  • Control unit: decodes instructions, drives the datapath
  • Memory holds instructions AND data (von Neumann)
  • Fetch → decode → execute, forever
  (pen marks: 5 )
  beat0:
     0: Now we have every piece needed for a computer.
     1: This is the layout of the Intel four zero zero four from nineteen seventy one, the first commercial single chip microprocessor, with about two thousand three hundred transistors.
  beat1:
     0: Every processor has the same main parts.
     1: The datapath: registers that hold values, and an arithmetic logic unit, the A L U, that adds, subtracts and does logic operations.
     2: The control unit is a big state machine that reads each instruction and drives the datapath.
  beat2:
     0: And memory holds both the program's instructions and its data, an arrangement called the von Neumann architecture.
  beat3:
     0: The C P U runs one loop forever.
     1: Fetch: read the instruction at the address in the program counter.
     2: Decode: figure out what it means.
     3: Execute: do it, using the A L U and registers.
     4: Then move to the next instruction.
     5: A modern processor does this billions of times per second.
     6: You'll design one of these yourself, in V H D L, in the computer design course.
