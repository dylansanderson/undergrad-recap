[s1] V  What computer engineers do
  img: a:eniac / a:fpga_board / a:robot_arm
  • Bridge hardware and software
  • Design chips, boards, embedded systems and the code that runs them
  • From ENIAC (1945) to billions of transistors per chip
  • Phones, cars, medical devices, robots, data centers
  beat0:
     0: Computer engineering sits between electrical engineering and computer science.
     1: Computer engineers design the hardware that computes, and write the software that runs closest to it.
     2: This is ENIAC, one of the first general purpose electronic computers, built in the nineteen forties with about eighteen thousand vacuum tubes.
     3: It filled a room.
  beat1:
     0: Today, a single chip holds billions of transistors, and computer engineers design them, often in hardware description languages on boards like this F P G A, which you'll learn to program.
  beat2:
     0: They also build embedded systems, computers hidden inside other products, from phones and cars to pacemakers and robots like this one.
     1: Every one of those systems needs people who understand both the transistors and the code.
     2: That's what this degree trains you to do.

[s3] V  The big idea: layers of abstraction
  img: fig:stack
  • Every layer hides the details of the one below
  • This degree climbs the whole stack
  • Physics → transistors → logic → processors → software
  • Engineers who understand several layers solve the hardest bugs
  (pen marks: 7 )
  beat0:
     0: One idea organizes the entire degree: abstraction.
     1: A computer is built in layers.
     2: Physics explains how electrons move.
     3: Transistors use that physics to make switches.
     4: Switches make logic gates, gates make processors, processors run instructions, and instructions build operating systems and applications.
     5: Each layer hides the details of the one below, so a programmer doesn't need to think about electrons.
     6: This degree is unusual because it climbs every one of those layers, from physics at the bottom to applications at the top.
     7: That's its real value: when something goes wrong at the boundary between layers, like a timing bug, a power glitch or a slow program caused by the cache, the engineer who understands more than one layer is the one who can fix it.
     8: Keep this picture in mind.
     9: At the end of the series, we'll come back to it.
